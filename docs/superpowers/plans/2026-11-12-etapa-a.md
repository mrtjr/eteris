# Éteris — Etapa A: vigia de preço, recorte ao vivo e tradução local — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Três funções nativas, todas locais:
- avisar quando o preço de uma página baixa ou quando um pedaço dela muda;
- mostrar um pedaço vivo de uma página numa janela pequena;
- traduzir páginas no próprio computador.

**Architecture:**
- **Vigia:** corre na janela dona da sessão. Um motor CefSharp escondido, numa janela própria fora do ecrã, visita a página de tempos a tempos e lê o preço ou o pedaço. A lógica (ler preços, decidir, agendar) é C# puro e testável; a leitura na página é um script injetado.
- **Recorte:** uma janela WPF pequena, sempre por cima, com um motor próprio e um estilo que isola o elemento.
- **Tradução:** o motor Bergamot (WebAssembly, MPL-2.0) corre numa página interna escondida, num esquema próprio sem rede. Os modelos da Mozilla vêm de uma release do Éteris no GitHub e são conferidos por SHA-256 antes de cada uso. O texto da página sai e volta por um script num mundo isolado.

**Tech Stack:** .NET 10 + WPF, CefSharp 156 (`CefSharp.Wpf.HwndHost`), Microsoft.Data.Sqlite, xUnit, Node (testes de sintaxe dos scripts), `@browsermt/bergamot-translator` 0.4.9 (WebAssembly), modelos `base-memory` da Mozilla.

**Spec:** `docs/viabilidade-etapa-a.md` (recomendações, provas medidas e as 8 decisões da secção 4).

## Global Constraints

- **Só começar depois de a 0.2.17 sair:** ramo novo a partir do `main` com a 0.2.17.
- **Não tocar em `src/Eteris.Browser/MainWindow.BrowserMenu.cs`.** As entradas no menu do navegador são a Task 15, depois de o trabalho da outra sessão fundir.
- **Textos:** interface e comentários em português europeu. Os textos exatos estão nas tarefas.
- **Vigias, privacidade:**
  - nunca na janela privada;
  - sem os cookies do utilizador por omissão, com a opção «com a minha sessão» por vigia (decisão 1);
  - o Escudo vale sempre.
- **Vigias, ritmo:**
  - intervalo mínimo 30 min, omissão 120 min;
  - nada corre com o Éteris fechado (decisão 2).
- **Avisos:** só dentro do Éteris, com o aviso interno e o piscar na barra de tarefas. Nada de ícone na bandeja nem de notificações do Windows (decisão 3); o `LicenseComplianceTests.Project_DoesNotPullTheWindowsSdkProjection` continua a passar.
- **Proteções dos sites (decisão 8):** o Éteris nunca as contorna — nada de resolver CAPTCHA, mudar o agente para escapar a desafios ou falsear impressões digitais. Um site que barra visitas automáticas passa a ser lido só quando o utilizador abre a página.
- **O motor da vigia recusa** transferências, janelas novas, pedidos de permissão, diálogos e som.
- **Modelos de tradução (decisão 4):**
  - só de `https://github.com/mrtjr/eteris/releases/download/modelos-traducao-1/`;
  - cada ficheiro é conferido por SHA-256 fixado no código antes de cada carga;
  - um ficheiro que não confere é apagado e nunca carregado.
- **Línguas (decisão 5):** pt↔en e es↔en; es↔pt passa pelo inglês e só fica se a memória medida na Task 10 não passar de 900 MB.
- **Português (decisão 6):** um só modelo «pt», e a interface diz que mistura pt-PT e pt-BR.
- **O motor de tradução:**
  - não tem rede: só o esquema `eteris-tradutor://`;
  - existe um de cada vez;
  - é largado ao fim de 5 min sem uso (custa ~540 MB, medido).
- **Interruptores de teste** (`ETERIS_TEST_*` e `--eteris-test-command`): ignorados pela versão instalada (`TestSwitches.IsInstalled`), como os existentes.
- **Comandos:**
  - testes unitários: `dotnet test tests/Eteris.Browser.Tests --filter "FullyQualifiedName~<Classe>"`;
  - testes ao vivo: `dotnet build src/Eteris.Browser` e depois `dotnet test tests/Eteris.Browser.E2E.Tests --filter "FullyQualifiedName~<Classe>"`.

## Review Focus

1. **Preços com espaço inseparável ou fino e símbolo colado** («R$\u00a01.299,90», «1\u202f299,90\u00a0€», «R$1.299,90»). Devem ler-se como 1299,90. → Task 1, `Parse_HandlesNbspAndGluedSymbols`.
2. **Página com vários preços** (prestações «12x R$ 49,02», «de R$ 742,34 por R$ 588,22»). Conta o preço dos dados estruturados, nunca o primeiro número do texto. → Task 3, `Parse_PrefersStructuredPriceOverInstallments`.
3. **Desafio anti-robô ou página vazia.** Nunca dá «o preço mudou» nem «o pedaço desapareceu»; conta como bloqueio. → Task 2, `Outcome_ChallengeIsNeverAChange`.
4. **Vigia apagada a meio de uma verificação** (ou o Éteris a fechar). Gravar o resultado não ressuscita a vigia nem dá erro. → Task 4, `Record_OnDeletedWatch_ReturnsFalse`.
5. **Tradução de página com formulários, `contenteditable`, código e `translate="no"`.** Esses ficam intactos, e «Mostrar original» repõe o texto exatamente. → Task 11, `Translation_LeavesFormsAndCodeAndRestoresExactly`.

- Produces:

  - `PageTranslationScripts.Apply(string json)`;
  - `PageTranslationScripts.Restore`;

**Algoritmo do `Apply`** (o método do Firefox; os testes não o determinam):
1. O `Collect` copia o `innerHTML` do bloco para um modelo e marca cada elemento em linha com `x-t="k"`, só na cópia. No `WeakMap` deste mundo, guarda o elemento original pelo `k` e os nós-filhos originais do bloco, para o `Restore`.
2. O `Apply` lê o HTML traduzido para um `<template>` e percorre-o recursivamente. Cada elemento `[x-t=k]` é trocado pelo elemento original `k` — o mesmo elemento, movido, para manter os seus ouvintes de eventos — depois de os filhos desse elemento serem trocados pelos traduzidos (recursão). Os nós de texto entram como estão.
3. O bloco recebe o resultado com `replaceChildren`.
4. O `Restore` repõe os nós-filhos originais de cada bloco traduzido.
